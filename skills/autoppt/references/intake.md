# ⓪ 了解老师的课 → ① 课程内容设计

每位老师的课都不一样。**先弄清楚老师要教什么、教给谁、怎么教，再做课件**——这一步省了，后面每一周都要返工。

## ⓪ 需求访谈
1. 先看老师给了什么：教学大纲、教材目录、旧课件（docx / pdf / pptx）——**先读，再问**，读得出来的不问。
2. 按 `templates/课程需求表.md` 问缺的项。有选择题工具时用它（如 Claude Code 的 AskUserQuestion）；没有时（如 Codex）用编号问题 + 备选项列在一条消息里。一轮最多问 4 个，先问最影响设计的：
   - 学生是谁、会不会编程；
   - 一共几周、每周几节、每节多长；
   - 每周大致讲什么（没有大纲时请老师按周列主题）；
   - 实践课做什么（编程 / 案例研讨 / 实验与数据分析 / 习题 / 写作展示 / 没有）；
   - 配图政策：能不能搜开放图库、能不能用 AI 生成、课件会不会公开；
   - 课件风格（展示 `styles/styles.jpg`，A / B / C 三选一）。
3. 老师说“你看着办”的项：用默认值（每周 2 理论 + 1 实践，45 分钟；风格 A；配图以自绘为主），在《课程内容设计》里标“假设”。
4. **快速模式**（老师只说了一句“帮我做一节关于 X 的课”）：只问学生是谁和风格两项，其余用默认值，直接做第一周；第一周交付后再补全需求表。

## ① 课程内容设计（交老师确认后才开始做课件）
产出 `课程大纲.md`（按 `templates/课程大纲模板.md`），核心是**周次表**：

| 周 | 主题 | 理论一 | 理论二 | 实践课 | 项目里程碑 | 本周主线（一句话） |
|---|---|---|---|---|---|---|

要求：
- **一条贯穿全课的线**：概念的先后顺序合理，前面埋的伏笔后面要用上；每周一句主线。
- **对齐老师的目标**：需求表第 4 项“最想让学生带走的 3 件事”在哪几周落实，写出来。
- **实践课与学科匹配**：
  | 学科类型 | 实践课可以是 | 互动可以是 |
  |---|---|---|
  | 理工、数据、计算 | 编程实践（Notebook，真实运行） | 参数滑块、模拟、可视化、现场计算 |
  | 医学、生命科学 | 病例研讨、读图判读、实验数据分析 | 读片判断、鉴别诊断选择卡、剂量 / 曲线计算器 |
  | 人文、历史、语言 | 史料研读、文本对照、写作与互评 | 时间轴、地图标注、史料对比、翻牌判断 |
  | 社科、经管、法律 | 案例分析、角色扮演、数据解读 | 决策模拟、选择卡、简单模型计算器 |
  | 艺术、设计 | 作品分析、草图与评图 | 色彩 / 构图对比、前后对照 |
- **难度与节奏**：每节 45 分钟约 20 页；新概念每节不超过 3 个；每节至少 1 个互动、1 次提问、1 个小测。
- **素材计划**：每周需要哪类图（自绘 / 数据图 / 真实照片 / 示意插图），从哪来（见 `images.md`）。

把《课程内容设计》交给老师：“这是整学期的安排，请改。改好后我从第 1 周开始做。”老师改过的版本就是以后每周设计文档的依据。同时建立《课件制作约定》，写入风格、配图政策、环境、红线。
