# 工作流程（给智能体）

整个流程分五个阶段。**前三个阶段是“和老师一起想清楚”，后两个阶段是“自己做完并验证”**。⓪① 每门课只做一次；每一周重复 ②③④。

```text
⓪ 了解课程（一次）   ──► ① 课程内容设计（一次）  ──► ② 第 N 周设计文档（每周）  ──► ③ 开干：实现  ──► ④ 验证与交付
   需求访谈、选风格         课程大纲.md（老师确认）      第 N 周 设计文档.md          weekNN/          截图、检查、链接、约定更新
                            课件制作约定.md              （老师按需修改）              含配图
```

⓪ 与 ① 的做法见 `intake.md`；配图见 `images.md`。

## 快速模式：一句话开始
用户只说了一句（“帮我做第 1 周的课件：人工智能概述，面向大一新生”）时，不要追问一长串。只问推断不出、且返工代价大的几项（学生基础、每周课时、风格），其余用默认值并在设计文档里写明“假设”；然后直接走 ②③④。课程大纲可以在做完第一周后再补全。

## ① 课程大纲（整门课只做一次；详见 intake.md）
- 用 `templates/课程大纲模板.md`。教师已有教学大纲（docx / pdf）时，先读它，把周次表抄进来，再问缺的几项（学生基础、运行环境、红线）。
- 同时建立 `课件制作约定.md`（`templates/课件制作约定模板.md`）。以后每一周学到的规矩、示例数据的已知结果都追加到这里。
- **请教师选风格**：展示 `styles/styles.jpg`，三选一——A 学术刊物（`academic`）、B 黑底舞台（`stage`）、C 几何色块（`blocks`）。选定后写进约定，以后每周 `new_week.py --style <风格>`。教师想要别的风格时，在 `engine/src/styles/themes/` 里新写一个主题文件（只覆盖变量和封面 / 章节 / 大字页），先做封面 + 大字页两张样张请教师确认。

## ② 第 N 周设计文档（每周，先写后做）
触发语：“设计第 N 周的课件” → 写设计文档 **并直接实现**；“设计第 N 周的课程内容 / 设计文档” → **只写文档**，等教师说“开干”。

1. 读：课程大纲、课件制作约定、上一周的设计文档与实践课结果、（如有）旧课件里对应的内容（**按内容对应，不按文件名周次**）。
2. 立主线：一句贯穿全周、可以当考题的话；三节课各回答它的一部分。
3. 按 `templates/周设计文档模板.md` 写：逐页表（标题、内容、时长）、新组件、数据与计算、事实核查清单、验收标准、需要教师确认的事。
4. **联网核对**每一个论文数字、日期、法规条文、产品信息；查不到的不写。在 §10 标“已联网核对”。
5. 交给教师。教师会按自己的实际需求改（加一个案例、换一个实验、缩短某一节）——**以修改后的文档为准**，不要把旧版本的想法带回来。

## ③ 开干：实现
```bash
python3 <skill>/scripts/new_week.py --dest <课程文件夹> --week N --course "…" --teacher "…" --school "…" --term "…" \
        --topic "…" --l1 "…" --l2 "…" --lab "…"
```
生成 `weekNN/`：三节课的页型样板、首页、学生指南、教师指南模板、构建脚本、实践课脚本模板。然后按这个顺序：

1. **数据先行**（编程类实践课）：`tools/toyN.py`（理论课互动的数据与对照值）、`tools/run_lab.py`（实践课代码，真实运行 + 自检）。先跑通，拿到真实数字，再写页面——讲稿里引用的数字必须来自这里。
2. **配图**：按 `images.md` 的顺序为每一页找图；需要真实图片时用 `scripts/find_images.py` 搜开放许可图库并登记来源。
3. **组件**：需要的新互动写进 `src/components/`（见 `components.md`）。浏览器里的计算与 Python 逐项对照。
4. **三节课**：按设计文档逐页写（见 `authoring.md`）。每页都有教师备注；每页一个核心观点。
5. **配套页**：首页、学生指南、事实出处（sources.html）、教师指南模板、README、TESTING。
6. `python3 build.py`：学生版、教师指南的分钟级安排、图片来源、字体子集。

## ④ 验证与交付
```bash
bash <skill>/scripts/check_week.sh weekNN      # 构建 → 冒烟测试 → 版式检查 → 逐页截图与总览图
```
- **逐张看总览图**（`weekNN/_shots/*_sheet*.png`），不要只看脚本输出：文字压线、图太小、空白太多、颜色不对，脚本发现不了。
- 互动逐项测试：每个按钮、滑块、重置；JS 与 Python 对照（写进 TESTING.md 和 checks.json）。
- 需要教师机运行的部分：用假数据（如 `XXX_FAKE=1`）测一次版式，**测完恢复占位**。
- 交付：写进课程文件夹；上一周首页加“第 N 周 →”（new_week.py 会自动加）；把本周学到的规矩追加到 `课件制作约定.md`。
- 给教师的总结：做了什么（每节课一两句 + 几个真实结果）、怎么验证的、**需要教师确认的事**（课前要运行的脚本、提交方式、可选内容）。

## 和教师沟通的习惯
- 先说要做什么，再做；中途有阶段性成果（设计文档、第一节课）就发出来，方便尽早纠偏。
- 不确定、且返工代价大的事（课程定位、项目设计、是否引用某个人的工作）才问；能从大纲、约定、上一周推断的不问。
- 结束时只讲结果和需要确认的事，不复述过程。
